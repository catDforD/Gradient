# 整理面经题库

把面经中的题目按知识类别整理进题库。所有路径相对于本知识库根目录。

## 输入

$ARGUMENTS

- 若上面给出了具体面经文件路径，只处理该文件。
- 若为空，扫描 `20-Areas/实习与求职/面试题与经验/` 下除 `题库/` 和 `面试题与经验索引.md` 之外的所有面经 `.md`，跳过其「相关笔记」以外已在题库中覆盖的文件；无法判断时逐个询问用户要处理哪些。

## 固定的 9 个知识类别

题库目录为 `20-Areas/实习与求职/面试题与经验/题库/`，类别与文件一一对应，不得新增或改名：

1. `Agent架构与编排.md` —— Agent 循环、ReAct / Plan-and-Execute、Single vs Multi-Agent、LangGraph 子图 / State / Checkpoint、工作流与状态机
2. `工具调用与协议.md` —— Function Calling / MCP / Skills 概念边界、Skills 知识进化、MCP 工程化、SSE / WebSocket / Streamable HTTP
3. `RAG与知识库.md` —— RAG 流程与评估、混合检索、多阶段召回、向量索引与存储、多模态 RAG、GraphRAG、文档解析
4. `上下文记忆与Prompt工程.md` —— 上下文窗口与遗忘、长短期记忆、记忆压缩、Prompt / Context / Harness 边界、幻觉与可靠性
5. `模型基础与训练.md` —— Transformer / KV Cache / MHA、LoRA 与微调、蒸馏、选型、PPO / DPO / GRPO、持续学习、论文讲解
6. `后端工程八股.md` —— Java 集合 / Spring / 并发线程池 / JVM / MySQL / Redis / TCP
7. `系统设计与场景题.md` —— Agent 应用场景设计、高并发系统、业务落地与工程素养
8. `算法手撕.md` —— 数据结构手撕题、模型相关手撕题、数学递推题
9. `AI Coding与工程素养.md` —— AI Coding 现场实操、效果评估、工具使用经验、角色与观点

归类拿不准时：优先按题目考察的核心知识归类；纯项目深挖、自我介绍、指标口径类题目**不进题库**，留在原面经中。

## 整理流程

1. **通读面经**，逐题判定类别；读面经的 YAML frontmatter 记录出处标识。
2. **去重**：逐个读取题库现有文件，已存在的题目不再重复收录；若同一题目在新面经中再次出现，在已有条目上补充新出处链接并确认其 🔥 标记（多份面经重复出现时打 🔥）。
3. **写入题库**，每道题保持既有格式，放在对应小节内（小节主题按现有文件结构，没有合适小节时在文件末尾新建 `## ` 小节）：

   ```
   - **原题（保留口语化原文，可括号补注考点）**（🔥 多次出现时加）—— 一句话考点要点 / 答题方向。出处：[[面经文件的完整 wiki 链接|出处缩写]]
   ```

   出处缩写规则：汇总类面经用「汇总A·面经01」式缩写（按面经文件中出现顺序 A/B/C…），单场面经用「公司·标识」如「小红书·服务端」。新文件出现时在 `面试题与经验索引.md` 登记缩写含义。

4. **更新 `面试题与经验索引.md`**：
   - 「面经原始记录」小节补充新面经条目（一句话概括覆盖主题）；
   - 「题库（按知识类别）」表格中对应类别的「出现频率」列如变化则更新（按 X/N 份面经计）；
   - 「备考优先级」小节只在出现频率发生明显变化时修订。
5. **更新 MOC**：`50-Maps/实习与求职.md` 的入口描述一般无需变动，仅当新增题库文件或类别时更新。

## 质量要求

- 题目原文尽量保留原帖表述；原帖缩写存疑的（如 `RCG`、`flux`）保留原文并标注「待核实」。
- 每道题必须有出处回链，否则宁可不收录。
- 不修改面经原始文件的内容，只读取。
- 新写的条目风格与题库现有内容保持一致：列表项、粗体原题、破折号后接考点。

## 收尾

- 用 grep 或脚本抽查本次新增条目中的 wiki 链接目标文件是否都存在。
- 完成后向用户报告：处理了哪些面经、每个题库各新增多少题、哪些题目打上了 🔥；然后提交 git（提交信息：`docs: 整理面经 <面经标识> 入题库`）并推送。
