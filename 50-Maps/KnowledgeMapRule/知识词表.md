# 知识词表

本笔记是本库的受控词表，也是 `topic/*` 标签和知识节点 `domain` 字段的唯一来源。2026-09-24 完成首轮收敛（旧值 29 个 → 现 24 个）。

知识节点的 `domain` 只使用一级值：`agent`、`llm`、`rag`、`engineering`、`science`。二级主题仍然可以作为 `topic/*` 标签；如果它需要参与节点之间的层级关系，就使用 [[本体登记]] 中的 `broader_than`。

## 取值规则

- **一级域不随意新增**。要加新的二级主题，先在本笔记登记，再用于笔记；确实需要新一级域时，必须同步修改 [[本体登记]]。
- **具体技术点不进 `topic`**。PTC、PImpl、RLM 这类细粒度对象将来交给「概念笔记」承载，`topic` 只标到域或子域。
- **横切标记不参与知识图谱**。`topic/career`、`topic/graduate`、`topic/open-source`、`topic/science-fiction` 只用于识别笔记范围。

## topic 的用法

`topic/*` 是笔记的**主题标签**，用于搜索、筛选、统计和把笔记接入 MOC。它可以多选，不表示节点之间存在某种语义关系。

给普通笔记加主题时，在 frontmatter 中写完整的词表值：

```yaml
tags:
  - topic/agent/tool-calling
```

使用以下规则：

- 只使用本页已经登记的值，不临时发明 `topic/ptc`、`topic/harness-design` 之类的新标签。
- 默认选择**最具体的一个或多个主题**。一篇笔记同时涉及工具调用和上下文记忆时，可以写两个 `topic/*`。
- 只有内容确实覆盖整个上级领域时，才额外使用 `topic/agent` 这类宽主题；不要因为用了 `topic/agent/tool-calling` 就重复加 `topic/agent`。
- 具体概念名、工具名和方法名不放进 `topic`。它们应通过知识节点标题、`aliases`、`relations` 或正文表达。
- `topic/career`、`topic/graduate` 等横切标签可以和知识主题同时出现，但只表示笔记的使用场景，不参与知识图谱关系。

例如，PTC 笔记可以这样写：

```yaml
type: concept
domain: agent
tags:
  - topic/agent/tool-calling
```

这里 `domain` 是知识节点的单一一级领域，`topic/agent/tool-calling` 是可用于筛选的更细主题；两者承担不同职责。

## 与题库九类的关系

题库的九个类别里有八个能一一对应到本词表的二级主题（Agent 架构与编排、工具调用与协议、RAG 与知识库、上下文记忆与 Prompt 工程、模型基础与训练、后端工程八股、算法手撕、AI Coding 与工程素养）。第九类「系统设计与场景题」是**题型**而不是知识域，对应到 `topic/engineering/system-design`。

## type 的使用规则

`type:` frontmatter 字段是笔记类型的唯一事实来源。`type/*` 标签属于旧格式，迁移完成前可以保留，但不再据此判断类型。

知识图谱节点的 `type` 只能是 `concept`、`method` 或 `entity`，规则见 [[本体登记]]。`moc`、`project`、`book-note`、`source-note` 等是普通笔记类型，不自动进入知识图谱。

`topic/*` 是可多选的主题标签；`domain` 是知识节点必填的单一一级领域。两者不要互相替代。

旧笔记中的 `type/*`、`clippings` 和其他历史取值暂时不批量改写，后续迁移时再统一处理。

## 校验方式

扫描与收敛脚本在 `tmp/vocab/`：`scan.mjs` 输出词表清单，`converge.mjs` 按映射改写（默认 dry-run，加 `--apply` 才写盘）。`tmp/` 是临时目录，若要长期复用，建议把扫描固化成 `.zcode/commands/` 下的斜杠命令。
