# 本体登记

本文件是知识图谱的字段手册。它规定哪些值可以写、每种关系是什么意思，以及录入时需要检查什么。

本文件只约束知识图谱节点。`type: moc`、`type: project` 等普通笔记类型不属于下面的节点类型。

## 一、节点类型

| 类型 | 用途 | 判断方法 | 示例 |
| --- | --- | --- | --- |
| `concept` | 概念、机制、现象、术语、理解框架 | 主要回答“是什么” | 上下文压缩、编排开销 |
| `method` | 可复用的方法、算法、流程、模式 | 主要回答“怎么做”，能说明适用条件或步骤 | RAG、ReAct、Leiden 社区发现 |
| `entity` | 具体存在的工具、系统、论文、组织、标准 | 可以被指认和追溯，重点是“哪个对象” | MCP、Codex、MAS² |

判断顺序：先问它是不是一个具体对象；如果不是，再问它是否是一套可执行的方法；两者都不是时使用 `concept`。专门名称本身不能决定类型，专门名称的方法仍然可以是 `method`。

## 二、关系类型

关系方向统一为“当前节点 → 目标节点”。关系值使用 Obsidian 内部链接，例如 `[[上下文压缩]]`。

| 关系 | 含义 | 起点 | 终点 | 备注 |
| --- | --- | --- | --- | --- |
| `broader_than` | 当前节点是目标节点的更具体主题 | `concept` / `method` | `concept` / `method` | 用于主题层级；允许多个目标 |
| `instantiates` | 当前节点是目标概念的一个实例、实现或典型案例 | `entity` / `method` | `concept` | 允许多个目标 |
| `prerequisites` | 学习或使用当前节点前需要掌握的内容 | `concept` / `method` | `concept` / `method` | 允许多个目标；只写直接前置 |
| `related` | 两个节点有明确但较弱的关联 | 任意 | 任意 | 对称关系；只登记一次 |

`broader_than` 表示主题层级，不表示物理或软件组成关系。以后确实需要表达“某部分属于某系统”时，再单独增加 `part_of`。

v0.1 暂不使用 `causes` 和 `contrasts`。前者需要因果证据，后者需要明确的混淆边界，等出现真实案例后再登记。

## 三、节点字段

| 字段 | 是否必填 | 规则 |
| --- | --- | --- |
| `id` | 是 | 使用 `node:<规范名>`，与节点类型无关；全局唯一，分配后不修改 |
| `type` | 是 | 只能是 `concept`、`method`、`entity` |
| `domain` | 是 | 只能使用 [[知识词表]] 登记的一级领域 |
| `aliases` | 否 | 其他写法；发现两个节点共用同一别名时，进入消歧处理 |
| `sources` | 是 | 至少一条来源，可以是内部链接、URL 或自己的研究记录 |
| `relations` | 否 | 只能使用本节登记的关系键；目标写内部链接 |
| `attributes` | 否 | 只放不会成为独立节点的字面量，不在这里写关系 |
| `confidence` | 否 | 当前节点定义的可信度：`高`、`中`、`低` |
| `status` | 是 | `active`、`merged`、`deprecated` |
| `merged_into` | 条件必填 | 只有 `status: merged` 时填写，指向新的节点 |

`domain` 只能写一级领域，例如 `agent`；`agent/harness` 这类二级主题写成 `broader_than` 关系或 `topic/*` 标签。

## 四、录入约束

1. `id` 不得重复，也不得因为改名或重新分类而改变。
2. `type`、`domain` 和关系键必须在本文件或 [[知识词表]] 中登记。
3. `sources` 至少保留一条，无法追溯来源的内容先留在 `00-Inbox/`。
4. 关系目标不存在时标记为“待建节点”，不把它伪装成已存在的笔记。
5. 不要手写 `prerequisites` 的传递闭包，也不要把 `related` 在两端重复写一遍。
6. 根节点可以没有上位关系；只有没有任何有效连接的非根节点才算孤立节点。
7. `attributes` 的键不得与关系键重名。

## 五、以后再加的能力

以下内容暂时属于后续工具能力，不是人工录入要求：

- 根据 `related` 自动生成反向边。
- 根据 `broader_than` 和 `prerequisites` 查询传递结果。
- 扫描不存在的目标、重复 ID 和别名冲突。
- 为单条关系记录独立的来源与置信度。
