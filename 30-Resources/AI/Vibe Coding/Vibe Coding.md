# Vibe Coding 心法

相关：[[AI 与 Coding]] · [[Claude Code]] · [[Coding Agent 工具与渠道]]

## 初识 Vibe Coding
我是从25年12月末开始接触 vibe coding 的。当时在实现一个科研上的 idea ，恰逢 gemini3 pro 在全网爆火，我就喜欢用它来写代码、测试和迭代。由于我本身代码能力只能算垃圾，仅仅接受过以 C 语言为基础的一些计算机课程教育，所以拿来应付稍微复杂一些的项目就有些捉襟见肘了。同时随着 AI coding 大行其道，轻轻松松就能像模像样的完成我提出的 idea （虽然我看不明白，也没有耐心去磨），这就导致我的每一次 AI coding 编程都随着对话切换而结束（也随着项目代码量上升而濒临崩溃，喜欢堆 shi 山是这样的）。    
既然 gemini 解决不了我的问题，我又尝试了 gpt-5.2 （更是依托，主要是会写很复杂的代码，报需要自己在网页端和终端来回切换，和 gpt 扯皮）。然后我转着转着就去试了一下 claude 网页端，初见时对我稚嫩的心灵产生了极大的震撼，claude 是会根据你的需求制定计划，然后在内部编写好整个项目并测试，完成后整体打包给你直接下载（其实就是 claude code cli 的逻辑），由此我了解到了 claude code cli 这个 vibe coding 工具。  
## Vibe Coding 工具大乱斗
接触到 cc 以后便一发不可收拾，claude 官方模型太贵，学生党支撑不起就尝试了两家宣传比较出名的国内模型厂商智谱和 Minimax 。理性来说， glm-4.7 、Minimax-2.1 确实没办法和 claude 最新模型比，但是 1/70 的价格能够达到 claude-ops-4.5 60%-70% 的性能，性价比这方面没得说（用于复杂项目会有很多问题，但是实现一些不复杂的小项目还是没什么问题）。  
之后陆陆续续又上手了 opencode ， codex （gpt-5.2-codex）。接触的工具越多，我却发现我越焦虑，现在 vibe coding 工具更新太快了，今天王炸明天颠覆的，我光滑的大脑皮层仿佛快被这些工具炸出褶皱了。说到底，我害怕 *落后* 在这个 AI 飞速发展的时代，我想要掌握这个时代最有力的工具，不被时代所抛弃，以至于最后被 vibe coding 带来的打破旧时代编程范式的爽感所蒙蔽——这是 vibe coding 的革新，却不是我的。  
## 时代洪流中我们何去何从
我从不否认 vibe coding （或者 智能体）会带给世界巨大变化的可能性，这几乎是无法阻挡也不能阻挡的趋势，谁落后谁都会感觉到正在加速被世界抛弃。但是有个问题却困扰我很久：当自然语言变成新的编程方式，我这种半吊子 AI 领域学生和其它行业从业者有什么区别？甚至说当目标是同一款产品时，我会因为需求分析拆解不到位而被更会抓产品特点、更会提出需求的非专业人士薄纱。 vibe coding 真真切切让我十分焦虑，原因就在于此。
