## 项目背景

题主介绍的实习项目是教育平台中的自动切题 Agent：将一道大题的解析过程自动拆解成多个小题及对应讲解步骤，帮助学生分步学习。

## 面试题与回答要点

### 1. 自我介绍与项目背景

- 常规自我介绍。
- 介绍实习期间的自动切题 Agent 项目和个人负责内容。

### 2. 自动切题 Agent 的 7 步 Pipeline

截图中的回答流程为：

> 题目输入 → 意图识别 → 知识点提取 → 步骤拆分 → 难度评估 → 讲解生成 → 格式校验

每一步作为独立处理节点，串联形成完整的题目解析链路。

### 3. LangGraph 中三个子图如何传递数据

三个子 Agent / 子图分别为：

- Parser Agent：解析题目。
- Splitter Agent：拆分步骤。
- Generator Agent：生成讲解。

通过 LangGraph 的 `State` 机制传递数据：每个节点读取当前 State，处理后返回更新后的 State，再沿图的边传给下一个节点。截图中的标准答案使用 `StateGraph`、`add_node` 和 `add_edge` 构建三节点流程。

### 4. 为什么拆成三个子图，而不是一条 Pipeline

截图总结了四个维度：

| 维度 | 单条 Pipeline | 三个子图 Agent |
|---|---|---|
| 测试难度 | 端到端测试，问题定位困难 | 每个子图可独立测试 |
| 复用性 | 整体复用，灵活性较差 | 子图可单独复用 |
| 扩展性 | 改一处可能影响全局 | 新增子图不影响已有流程 |
| 错误隔离 | 一个节点异常可能影响全部 | 子图间可以隔离错误 |

### 5. 如何搭建 Skills 知识进化流程

截图中的流程为：

> 收集 → 提取 → 存储 → 检查 → 应用 → 反馈

流程要点：从使用过程中收集优质问答和修正结果，提取可复用技能，存储到知识库，经过检查后在新任务中检索并注入；再根据使用反馈持续迭代。

### 6. 为什么不直接把知识写进 Prompt，而使用 Skills

截图中对比的主要维度：

| 维度 | 硬编码 Prompt | Skills 方式 |
|---|---|---|
| Prompt 长度 | 知识越多越长 | 按需注入，控制长度 |
| 知识更新 | 修改 Prompt 后重新部署 | 更新知识库即可 |
| 多场景复用 | 不同场景需要不同 Prompt | 同一套 Skills 服务多个场景 |
| 可观测性 | 不知道用了哪些知识 | 可追踪检索和应用过程 |
| 维护成本 | 较高 | 相对较低 |

## 复习重点

- LangGraph 的 State、节点、边和子图组合方式。
- Agent 工作流拆分的测试性、复用性、扩展性与错误隔离收益。
- Skills 的收集、提取、向量化存储、检索注入和反馈闭环。
- Prompt Engineering 与动态知识注入的取舍。
- 能用一个具体项目解释 Agent 的输入、状态、节点输出和最终结果。
