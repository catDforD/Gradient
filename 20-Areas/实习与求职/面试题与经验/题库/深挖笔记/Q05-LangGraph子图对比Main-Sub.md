# Q05｜为什么拆成三个子图，而不是一条 Pipeline？—— 深挖：子图 vs Main-Sub 结构

> 出处：题库 [[20-Areas/实习与求职/面试题与经验/题库/Agent架构与编排|Agent架构与编排]] · 原始面经 [[20-Areas/实习与求职/面试题与经验/小红书-Agent开发实习生-一面面经-AIGC小白入门记|小红书·AIGC小白入门记]]、[[20-Areas/实习与求职/面试题与经验/小红书Agent开发实习生一面-百度Agent面经-杰尼龟|小红书/百度·杰尼龟]]

## 背景

深挖发生于 2026-09-19。用户读完 Q05 解答（为什么拆三个子图）后连续追问三轮：LangGraph 子图结构与 coding agent 常用的 main+sub-agent 结构有何区别？哪些场景子图更优？图结构是人工编排还是节点动态生成？本笔记固化这三轮问答。

## 追问 1：LangGraph 子图结构 vs coding agent 的 main+sub 结构，有什么区别？有什么优点？

核心区别：**「静态图编排」vs「工具调用式树」**。

| 维度 | LangGraph 子图结构 | main + sub-agent（工具调用式） |
|------|--------------------|-------------------------------|
| 架构模型 | 有向图（DAG + 条件边 + 子图嵌套） | 线性 + 树（main 串行调用 sub-agent） |
| 状态传递 | 共享 State（字段级 reducer，确定性合并） | 消息传递 / 临时文件 / 工具返回结果 |
| 路由方式 | 显式边 + 条件边 + Send API（运行时动态路由） | 固定 if-else / LLM router |
| 容错粒度 | 极细（子图级 checkpoint，可精确恢复） | 较粗（main 层或 sub-agent 内部有限重试） |
| 可观测性 | 强（LangGraph Studio 分子图调试、完整 trace） | 中等（trace 依赖框架，定位靠日志） |
| 复用性 | 子图可独立部署、单测、当"工具"复用 | 子 Agent 相对独立，但不易单独运行 |

四大优点：
1. **可控可回溯**：每步独立 checkpoint，失败从任意节点恢复，不用重头跑。
2. **状态一致性**：所有节点共享同一 State，字段级 reducer 保证确定性合并，无格式漂移。
3. **测试与调试**：Studio 分子图调试，可暂停、回放、对比；main+sub 的 trace 偏黑盒。
4. **复杂编排原语**：条件分支、并行扇出、子图嵌套、human-in-the-loop 断点原生支持。

## 追问 2：哪些情况下子图结构更优？

子图更优的五类场景：
1. **错误代价高、要精细容错**：长流程（10 步以上）、金融/法律等高风险场景、需要精确回滚、human-in-the-loop 断点多。
2. **要强可观测性**：生产级系统要完整 trace、团队协作开发要分子图调试。
3. **要强状态一致性**：不同阶段共享"进度 + 历史 + 质检结果"等全局状态，避免状态漂移。
4. **要高复用与模块化**：同一组子图被多个流程挂载；按阶段选型（采集用便宜模型、分析用强模型）。
5. **复杂图编排**：LLM 路由分支、并行 fan-out、子图嵌套、Send API 动态分发。

反过来，main+sub 更适合**快速原型、简单分工流水线**（如 main 规划 → 若干 sub-agent 各写一个模块）。生产级系统的推荐形态仍是混合：核心链路用图编排，非确定性环节留给子 Agent。

## 追问 3：图结构是人工编排的，还是有节点负责编排整个图？

**图结构由人提前编排，运行中没有节点会重新生成/改写整个图。**

- 人工编排：开发者用 `StateGraph`/`add_node`/`add_edge`/`add_conditional_edges` 提前搭好骨架，compile 之后图结构固定。
- 运行时动态只发生在**路由**上：路由节点（LLM）读 State 输出结构化决策（enum 节点名 / 意图标签），框架按条件边映射跳转；更动态的场景用 Send API 运行时分发，但动的只是"走哪条边"，不是图本身。
- 设计哲学：图是一个**静态可编程的程序**——可版本控制、可测试、可回放，这正是比黑盒循环可控可观测的根源。

## 核心结论

- LangGraph 子图 vs main+sub 的本质区别：静态图编排 vs 工具调用式树。
- 子图优势 = 细粒度 checkpoint（可恢复）+ 确定性 State（无漂移）+ 可视化调试 + 复杂编排原语。
- 选型判断：错误代价高、路径复杂、要审计回溯 → 子图；快速原型、简单分工 → main+sub；生产常态是混合（图骨架 + Agent 弹性节点）。
- 图结构 = 人工编排 + compile 固定；运行时只有路由决策是动态的，没有"节点重写图"。
