## 高频题（已出现多次）

- **最长递增子序列（LIS）**（🔥 出现两次：小红书两场）
	- O(n²) 动态规划 + O(n log n) patience sorting 两种写法都要会。
	- 出处：[[20-Areas/实习与求职/面试题与经验/小红书-Agent服务端开发实习-一面面经|小红书·服务端]]、[[20-Areas/实习与求职/面试题与经验/小红书Agent开发实习生一面-百度Agent面经-杰尼龟|小红书/百度·杰尼龟]]
  > [!success]- ✅ AI 解答 · Q16 · 2026-09-16
  > **🎯 标准答案（面试版）**两种写法都要会：①O(n²) DP：dp[i]=以 i 结尾的 LIS 长度，dp[i]=max(dp[j]+1 | j<i 且 nums[j]<nums[i])，答案为 max(dp)，记录前驱可恢复具体序列；②O(n log n) 贪心+二分（patience sorting）：tails[k] 维护「长度 k+1 递增子序列的最小尾元素」，每元素 bisect_left 定位替换或追加，tails 长度即答案。
  > **📌 要点**
  > - 严格递增用 bisect_left（相等元素不扩展长度），非递减用 bisect_right
  > - tails 不是具体 LIS（只保证长度正确），恢复序列要用 DP 前驱法
  > - 边界：空数组返回 0；全相同元素严格 LIS=1
  > - 变体：最长递增子序列个数、俄罗斯套娃信封（排序一维后做 LIS）
  > **🔬 原理深入**
  > patience sorting 直觉：牌面分堆、每堆递增、堆顶最小——新牌放最左的 ≥ 它的堆顶上，堆数即 LIS 长度；替换策略保证 tails 严格递增（归纳可证），二分使单步 O(log n)。DP 正确性来自最优子结构：以 i 结尾的 LIS 必由某个 j<i 的 LIS 延伸而来。追问：为什么二分而不是线性找？——总复杂度从 O(n²) 降到 O(n log n) 的关键，n=1e5 规模下 O(n²) 会超时。
  > **🔗 延伸**
  > 面试策略：先讲 O(n²) 暴力再主动优化到 O(n log n)，展示优化路径比直接背最优解更得分；与编辑距离同属「序列 DP → 贪心+数据结构优化」范式。
- **高并发优惠券系统（AI Coding 形式，完整交付）**（🔥 出现两次，见 [[20-Areas/实习与求职/面试题与经验/题库/系统设计与场景题]]）
	- 幂等、库存扣减、边界测试、README。
	- 出处：[[20-Areas/实习与求职/面试题与经验/AI-Agent与大模型岗位面经汇总-01至05-07-08|汇总A·面经04]]、[[20-Areas/实习与求职/面试题与经验/AI-Agent开发岗位面经汇总-2026年4月-01至07|汇总B·面经04]]
  > [!success]- ✅ AI 解答 · Q17 · 2026-09-16
  > **🎯 标准答案（面试版）**这是 AI Coding 现场交付题，考工程组织而非算法：先澄清需求（发券/抢券/核销三链路、一人一张？量级？）→ 架构（网关限流 → 无状态服务 → Redis 预扣库存 + Lua 原子性 → MQ 异步落库 → DB 最终一致）→ 关键实现（幂等唯一索引、Lua 原子扣减、削峰）→ 边界测试（重复请求、并发归零、超时回滚、消息重复）→ README + 可运行 Demo。
  > **📌 要点**
  > - 幂等：DB 唯一索引 (user_id, batch_id) 兜底 + Redis 去重 set 前置拦截
  > - 防超卖：Lua 脚本原子完成「查库存→扣减→写去重」，DB 层 CHECK 约束二道防线
  > - 削峰：抢券成功即返回，落库走 MQ；消费端幂等防重复发券
  > - 兜底：令牌桶限流、库存预热、Redis-DB 定时对账补偿
  > **🔬 原理深入**
  > 核心矛盾是行级热点：所有请求打同一行库存，DB 必然崩。解法是把扣减上移到内存型存储——Redis 单线程 + Lua 保证 CHECK-DEC-SET 原子；MQ 把瞬时写压摊平到消费速率。一致性边界：先 Redis 后 DB 的窗口内宕机会产生「已发未落」，用对账任务补偿而非强一致（牺牲实时性换吞吐）。追问：为什么不用 DB 乐观锁？低并发可以，高并发下大量失败重试纯耗资源；为什么要幂等？MQ 至少一次投递 + 用户重复点击都会造成重复。
  > **🔗 延伸**
  > 系统设计版详解见 [[20-Areas/实习与求职/面试题与经验/题库/系统设计与场景题]]；可引申秒杀架构与分布式锁（Redisson 看门狗）的正确用法。
